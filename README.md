# Dota Insights

AI-accessible analytics for Dota 2. A public MCP server you connect to Claude Code, Claude Desktop, Cursor
and other MCP clients, so your assistant can answer questions about heroes, items, economy, matches,
players and the pro scene from real match data.

Every result comes in one envelope: `status` (`ok`, `insufficient_data` or `error`), the result, the
sample size, filters, period, metric definitions, 95% confidence intervals, caveats and data sources.
When there are too few matches, `insufficient_data` carries a `hint` on how to widen the filters. When a
data source fails (rate limit, outage, missing STRATZ token, timeout), `error` says what happened and the
`hint` says whether and when to retry.

## Connect

The server speaks MCP over Streamable HTTP at `http://<host>:<port>/mcp` (default
`http://127.0.0.1:8000/mcp`). Start it locally with `uv run dota-insights` (see [Development](#development)).

**Claude Code**

```bash
claude mcp add --transport http dota-insights http://127.0.0.1:8000/mcp
```

Add `--scope user` to use it in every project. Check it with `claude mcp list`, or `/mcp` inside a
session.

**Claude Desktop**

For a server reachable over HTTPS, open Settings → Connectors → Add custom connector and enter its `/mcp`
URL. For a server on your own machine, bridge it with `mcp-remote` in `claude_desktop_config.json`
(Settings → Developer → Edit Config), then restart Claude Desktop:

```json
{
  "mcpServers": {
    "dota-insights": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://127.0.0.1:8000/mcp"]
    }
  }
}
```

Other clients (Cursor, VS Code, ...) take the same URL as a "streamable HTTP" MCP server.

## Data limitations

- **OpenDota free tier.** 60 requests a minute and 3,000 a day, shared by every user of a server. Results
  are cached (hero and item aggregates for hours, finished matches for a week), but a cold question that
  fans out over many heroes or matches can hit the limit; the tool then answers `error` with a retry hint.
- **Collector database.** Hero, matchup, item-timing and GPM/XPM percentile tools first read the
  aggregates the collector builds from ranked OpenDota public matches (`source` starts with
  `"dota-insights-db"`) and call the live APIs only when the database has no fresh data for the
  filters or too small a sample. Those aggregates group lettered patches under their major patch
  and cannot separate Immortal from Divine.
- **Few parsed matches.** Only about 8% of public matches are replay-parsed on OpenDota. Timelines,
  teamfights, wards, lane outcomes, purchase logs and per-minute farm exist only for parsed matches, so
  those tools say when a match is unparsed and aggregates over parsed data rest on smaller samples.
- **No separate Immortal bracket in OpenDota.** OpenDota aggregates fold Immortal into Divine (bracket 8
  is empty). Rank-filtered hero, item and build statistics come from STRATZ, which does separate
  Immortal; OpenDota-only tools treat `divine+` as the top bracket.
- **STRATZ.** STRATZ data needs a server-side API token (`DOTA_INSIGHTS_STRATZ_API_TOKEN`). Without it,
  STRATZ-backed tools return an `error` saying so and OpenDota-backed tools keep working. Results built
  from STRATZ list `"stratz"` in `source` and must credit it: data from [STRATZ](https://stratz.com).
- **Correlation, not causation.** Item, build and timing win rates describe the games where players made
  that choice; they do not prove the choice caused the win. Tools say so in `caveats`.
- **Public profiles only.** Player tools need an exposed match history; a private profile, or one with
  "Expose Public Match Data" off, gets an `error` saying so. Players can also ask the server's
  maintainer to be left out (see [Privacy](#privacy)): player tools then refuse them, and match
  tools show them without account id or name, like anonymous players.
- **Pro data** covers league matches OpenDota tracks; small tournaments and very recent games may be
  missing.

Data from [OpenDota](https://www.opendota.com) and [STRATZ](https://stratz.com). Dota 2 is a registered
trademark of Valve Corporation; this project is not affiliated with or endorsed by Valve.

## Development

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env
uv run dota-insights          # serves MCP over Streamable HTTP at http://127.0.0.1:8000/mcp
uv run pytest
uv run ruff check . && uv run ruff format --check .
```

Collector (needs `DOTA_INSIGHTS_DATABASE_URL`; see [docs/architecture/collector.md](docs/architecture/collector.md)):

```bash
uv run alembic upgrade head
uv run dota-insights collect list         # jobs and intervals
uv run dota-insights collect patches      # run one job now
uv run dota-insights collect run public-matches enrich aggregate --max-minutes 25
uv run dota-insights collect status       # budgets, last runs, stale patches, gaps
uv run dota-insights collect scheduler    # optional local loop; production uses GitHub Actions
docker compose up --build                 # local PostgreSQL + migrations + server
```

## Deploy

Production runs on Vercel (Hobby plan) as a serverless ASGI app, `dota_insights.mcp.asgi:app`,
loaded through the root `app.py` that Vercel detects. It is stateless: no MCP session survives between
requests, and responses are JSON rather than SSE. Only pushes to `main` deploy (to production);
other branches and pull requests get no deployment (`git.deploymentEnabled` in `vercel.json`).

Project environment variables in Vercel: `DOTA_INSIGHTS_STRATZ_API_TOKEN`, and `DATABASE_URL`
from the Neon integration (read when `DOTA_INSIGHTS_DATABASE_URL` is not set). Data collection
does not run on Vercel: GitHub Actions runs it on a schedule (`.github/workflows/collect.yml`,
see [docs/architecture/collector.md](docs/architecture/collector.md)), using the repository
secrets `DOTA_INSIGHTS_DATABASE_URL` and `DOTA_INSIGHTS_STRATZ_API_TOKEN`.

### Shared state (Redis)

Serverless instances share no memory. With Upstash Redis connected (Vercel Marketplace →
Upstash → Redis, linked to the project), the integration injects `UPSTASH_REDIS_REST_URL` and
`UPSTASH_REDIS_REST_TOKEN` (older Vercel KV stores: `KV_REST_API_URL` / `KV_REST_API_TOKEN`; all
are accepted, as is `DOTA_INSIGHTS_REDIS_REST_URL` / `_TOKEN`). Then all instances share:

- the source cache (`@cached`), keyed by function and argument hash with the function's TTL, in a
  generation that changes when the collector sees a new patch or a deploy ships newer patch data;
- server-wide source quotas: by default 50/min and 2,500/day for OpenDota (free tier: 60/min,
  3,000/day per IP) and 120/min and 4,000/day for STRATZ (token: 250/min, 10,000/day, also used by
  the collector). Over the minute cap a call waits; over the daily cap it gets an `error` envelope
  until midnight UTC. Set with `DOTA_INSIGHTS_{OPENDOTA,STRATZ}_SERVER_{PER_MINUTE,DAILY}`;
- per-client rate limits (below) and the alert throttle.

Without Redis, or while it fails (each command times out after 1.5 s, then Redis is skipped for
30 s), everything falls back to per-instance memory; no tool fails because Redis is down. A tool
call costs a few Redis commands (one rate-limit update, a lookup per cache miss in memory, one
quota update per source request); the Upstash free tier covers light public use. To let the
collector invalidate the cache on a new patch, add the same two variables as repository secrets.

### Rate limits

Each client IP (`x-real-ip` / `x-forwarded-for`, which Vercel sets) gets 30 tool calls a minute
and 1,000 a day; heavy tools (explorer queries, multi-hero and multi-match aggregates,
`explore_query`, `test_hypothesis`, `find_matches`, `predict_live_win`, ...) also count against
5 a minute and 150 a day. A call over a limit returns an `error` envelope whose hint gives the
seconds until the window resets. Configure with `DOTA_INSIGHTS_RATE_LIMIT_PER_MINUTE`,
`_PER_DAY`, `_HEAVY_PER_MINUTE`, `_HEAVY_PER_DAY` (0 disables one) or turn them off with
`DOTA_INSIGHTS_RATE_LIMIT_ENABLED=false`. Calls without an HTTP request (stdio) are not limited.

### Monitoring

- Every tool call logs one JSON line (logger `dota_insights.tool_calls`) with `duration_ms`,
  `status`, `sources` and `source_calls`, `cache_hit` / `cache_hits` / `shared_cache_hits` /
  `cache_misses`, `quota_left` (calls left today per source) and `rate_limited`. Vercel shows them
  under the project's Logs.
- `GET /status` returns source quota usage (minute and day), whether shared state is on Redis,
  the rate limits, and data freshness when `DATABASE_URL` is set: the last run of each collector
  job (status, start, finish, last success), the newest collected match and stale aggregate
  patches.
- Telegram alerts (optional): set `DOTA_INSIGHTS_TELEGRAM_BOT_TOKEN` (from @BotFather) and
  `DOTA_INSIGHTS_TELEGRAM_CHAT_ID`. The server then alerts when a source's daily quota passes 80%
  (`DOTA_INSIGHTS_ALERT_QUOTA_RATIO`) and when it is spent, and when at least half
  (`DOTA_INSIGHTS_ALERT_ERROR_RATE`) of at least 10 (`DOTA_INSIGHTS_ALERT_ERROR_MIN_CALLS`) tool
  calls in a 5-minute window fail. Each alert kind is sent at most once per 30 minutes
  (`DOTA_INSIGHTS_ALERT_THROTTLE_SECONDS`) across instances.
- Usage analytics: every tool call is stored as one row (`usage_events`): tool, argument shape
  (hero, item and patch names kept; player ids replaced by `<player>`; other strings cut to 200
  characters), status, error kind, message, latency, sources, cache hit, client name and version
  (MCP client info or `User-Agent`) and a client hash. Raw IPs are never stored: the hash uses a
  salt that rotates weekly and lives only in Redis. The server pushes each event to a Redis list
  (within `DOTA_INSIGHTS_USAGE_WRITE_TIMEOUT`, 0.5 s; a failure never affects the call); the
  collector's hourly `usage` job moves the list into Postgres and deletes calls older than 90
  days (`DOTA_INSIGHTS_USAGE_RETENTION_DAYS`) and feedback older than a year
  (`DOTA_INSIGHTS_FEEDBACK_RETENTION_DAYS`). `DOTA_INSIGHTS_USAGE_ENABLED=false` turns it off.
- Usage report: `uv run dota-insights usage report --days 30` (or `--json`), and
  `GET /admin/usage?days=30` with `Authorization: Bearer $DOTA_INSIGHTS_ADMIN_TOKEN` (404 when
  the token is unset or wrong). Calls and unique clients per day and week, success rate and
  p50/p95 latency per tool, top tools and clients, the most frequent `insufficient_data` /
  `error` calls, wrong-answer reports (`report_wrong_answer`, with the call they refer to) and
  questions no tool could answer (`suggest_feature`). `uv run dota-insights usage flush` moves
  the queue in now. Reports are limited to 3 a minute and 30 a day per client
  (`DOTA_INSIGHTS_RATE_LIMIT_FEEDBACK_PER_MINUTE` / `_PER_DAY`).
- Uptime: point an external monitor (UptimeRobot, Better Stack or similar; free tiers are enough)
  at `https://dota-insights.vercel.app/health` with a 5-minute interval, expecting HTTP 200 and
  the keyword `"ok"`. `/health` does no I/O, so it measures the deployment itself; use `/status`
  for quotas and collector freshness.

### Privacy

Players who ask not to be shown are kept in `player_opt_outs`:

```bash
uv run dota-insights privacy opt-out 56939869 --note "email 2026-11-04"
```

`privacy opt-in <player>` removes a player and `privacy list` lists them; `<player>` takes an
account id, SteamID64 or profile URL. Player tools (and `get_pro_player`) answer an opted-out
player with an `error`; match tools and peer lists replace their account id and names with
`null`. Instances pick up a change within about a minute.
